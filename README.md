> ## ⚠️ 必须外接地图服务

## 它解决什么问题

十年前的运动手表不记地名。它只记：**时间、坐标、距离**。

导出来是一堆这样的行（下面三行是**示例坐标**，不是真实位置）：

```
2014-09-22 21:54:49, 39.9088, 116.3975, 5.21
2014-09-24 22:07:13, 39.9091, 116.3972, 4.88
2014-09-27 21:41:06, 39.9085, 116.3978, 6.03
```

坐标能看，但你不知道那是哪儿。**十年后连自己都忘了。**

这个工具做的事：把每一行坐标送回地图问「这是哪儿」，拿回省 / 市，然后按城市统计次数，
做成词云——字号就是你在那座城市跑了多少次。

## 三样产出

| 产出 | 说明 |
|---|---|
| **城市匹配表** | 原表 + 省 / 市 / 区 / 行政区码 / 可信度分级 |
| **频率统计** | 每个城市多少次、多少公里、第一次去的年份 |
| **词云页** | 单文件 HTML，离线可开，不联网、不上传 |

词云页的阅读顺序：**四个关键数 → 词云 → 城市表 → 年份表 → 24 小时分布 → 验证过程**。

## 第 0 步 · 申请腾讯地图 Key（必做）

一句话：**登录 → 建应用 → 添加 Key → 分配额度**，四步，个人开发者免费。

| 步 | 在哪 | 做什么 |
|---|---|---|
| 1 | [lbs.qq.com](https://lbs.qq.com/) 右上角「登录 / 注册」 | 微信或 QQ 扫码即可。之后完成**个人实名认证**——不认证一般拿不到配额 |
| 2 | 控制台 → **应用管理 → 我的应用 → 创建应用** | 应用名随便填（如「跑步城市词云」），应用类型选「个人」或 Web 端 |
| 3 | 应用详情页 → **添加 Key** | Key 名随便填。**必须勾上「WebServiceAPI」**——本工具走服务端接口，只勾 JavaScript API 会调不通。域名白名单本地测试填 `*` |
| 4 | 控制台 → **配额管理 → 账户额度 → 一键分配** | **最容易漏的一步**：Key 建好不等于能调，额度没分到这个 Key，接口会直接报错 |

四步走完，把 Key 填到下面命令的 `--key` 里就行。

> **Key 不要提交到 git**。本文所有示例都用 `你的KEY` 占位，仓库里带了 `.gitignore`。
> 免费额度每天有多少次，以控制台「配额管理」页显示的为准——平台会调整，本文不写死数字。

## 快速开始

```bash
# 1. 先按上面「第 0 步」把 Key 申请下来（个人开发者免费）

# 2. 先拿 20 条试跑，确认通
python tools/geocode_tencent.py \
    --in examples/points-sample.csv \
    --key 你的KEY \
    --out demo-out.csv \
    --limit 20

# 3. 通了再全量
python tools/geocode_tencent.py --in your-points.csv --key 你的KEY --out cities.csv
```

输入 CSV 只要有两列坐标，表头认这些名字：

```
lat / latitude / 纬度        lon / lng / longitude / 经度
```

其它列原样保留。输出多六列：

```
province, city, district, adcode, level, note
```

### `level` 是什么意思

| 级别 | 拿到什么 | 怎么用 |
|---|---|---|
| **A** | 省 + 市 + 区 | 直接用 |
| **B** | 有市、没区（郊区常见） | 可以用 |
| **C** | 只到省 | 单独归一类，**别硬塞成某个市** |
| **D** | 判定不了（境外 / 海上 / 无返回） | **留空，不猜** |

> D 级留空是故意的。**宁可缺一条，不要编一条。**

## 四条判据（结果准不准，全看这个）

### 1. 坐标要先转基准

运动手表记的是 **WGS-84**，腾讯地图用 **GCJ-02**。国内两者差几百米。
城市中心无所谓，**城市边界会判错市**。脚本已经内置转换，别去掉。

### 2. 请求要限速

个人 key 一般 5~10 QPS。超了会被限流，返回 `status 120/121/122`。
脚本默认 `--qps 5`，失败会退避重试，别调太猛。

### 3. 结果要缓存

默认写 `.geocode_cache.json`。同一坐标只问一次，重跑不再花额度。

### 4. 要验，不能直接信

拿一批**本来就有地名**的记录当标准答案（后来换的表、别的设备都行），
只用坐标让引擎盲判，逐条比对。**准确率低于 99% 就别用。**

这一步不能省。补出来的城市是给人看的，错一个，整篇东西的可信度就没了。

## 隐私红线

坐标等于住址。

- ❌ 原始 CSV **不要**传 GitHub、不要发群、不要截图
- ❌ 逐点的热力图**不要**对外发——那是家庭住址与常去路线
- ✅ 对外只放**城市级聚合**（城市 + 次数 + 距离）
- ✅ 交付页做成**单个 HTML 文件**，双击即开，零外部请求

仓库里的 `examples/points-sample.csv` 是公开地标，不是任何人的轨迹。

## 换别的地图服务

| 服务 | 坐标基准 | 要改什么 |
|---|---|---|
| 腾讯地图（本文示例） | GCJ-02 | 不用改 |
| 高德 | GCJ-02 | 改接口地址与返回字段 |
| 百度 | **BD-09** | 要在 GCJ-02 之后再转一步 |
| 天地图 | CGCS2000 | 接近 WGS-84，可不转 |
