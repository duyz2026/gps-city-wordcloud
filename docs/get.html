GPS 定城市匹配和频率词云

把只有经纬度的记录，
补成城市，再做成一张词云

如果你手上有一堆带着坐标、却没有地名的数据——老运动手表、行车记录、照片 EXIF 都算——这套工具就是干这个的。原文件不会被改动，城市名会写进一个新文件。

三步 不装任何软件，只要有 Python

  1. 导出数据成 CSV：时间, 纬度, 经度, 距离。少一两列也能跑，坐标必须有。
  2. 申请腾讯地图 Key（免费的额度够跑几千条）：
    开发者页面登录 → 创建应用 → 添加 Key，必须勾 WebServiceAPI；
    再去「配额管理 → 账户额度 → 一键分配」把额度分给这个 Key。
    最后这一步最容易漏，漏了接口会直接报错。
  3. 跑脚本，看结果：tools/geocode_tencent.py。跑完会多一个带 city 列的文件， 以及一份「判不了」的清单——判不了的会留在清单里，不会硬猜。

包里有什么

  • GUIDE.md　完整的操作手册：六步主流程、四道验收门、六个常见的坑
  • tools/geocode_tencent.py　坐标转城市，含 WGS84→GCJ02 换算和四级置信判定
  • examples/points-sample.csv　示例数据，是公开地标，不是你我的真实位置
  • README.md　五分钟看懂它在干嘛

几个常问的

链接打不开 / 一直转圈？
这个站托管在 GitHub，国内偶尔抽风。换流量或换 WiFi 试一次，或者隔十几分钟再点。还是不行，就把网址复制到电脑浏览器里开。
我完全不会写代码，能用吗？
能看懂结果，但不能自己跑——脚本要在命令行里执行。建议先只做第 1 步：把数据导出来存好。数据在自己手里，什么时候都不晚。
我没有经纬度，只有时间和距离？
那这套用不上。城市名只能从坐标反推出来，没有坐标就无从下手，这不是工具的问题。
能换成高德或百度吗？
可以，改脚本里的接口地址就行。但坐标系不一样：腾讯、高德是 GCJ-02，百度是 BD-09，天地图是 CGCS2000。换算错了整张图会整体偏移，不会报错——这种错最难发现。
我跑出来的城市怎么比实际少？
正常。离得远、漂移大、定位丢掉的记录会被判为「判不了」而留在清单里，不会硬塞一个城市名。手册里写了怎么逐条核对。
